## 0. 一页纸摘要

**一句话**：给现有系统加一个「手机专用页面 `/m/`」，在家 Wi-Fi 下用 Android Chrome 打开，像 App 一样看行情、看曲线、管自选；后端 API 契约不变，桌面端零改动。

| 维度 | 决策 |
| --- | --- |
| 路线 | 响应式网页 + 轻量 PWA（不做原生 App、不做小程序） |
| 页面 | 独立移动端入口 `/m/`，桌面 `/` 不动 |
| 网络 | 只做局域网：`HOST=0.0.0.0` + Windows 防火墙放行 + 路由器固定 IP |
| 鉴权 | 可选 token 开关（默认关闭，保持现状）；开启后**本机免 token**、局域网必须带 token |
| 数据 | 完全复用现有 `/api/*`，不新增业务接口 |
| 推送 | 本版本**不做**（列为 M6.5 可选，走 ntfy/Bark，不依赖 HTTPS） |
| 工期 | 3.5 人日（M6.0 ~ M6.4），可选 +1 人日 |
| 风险 | 最大风险是「手机能连上但页面难用」，所以先做 M6.0 真机验证 |

**不做什么**（防止范围蔓延）：

- ❌ 不做原生 App / 上架应用商店 / 套壳 APK（个人自用无收益，成本高）
- ❌ 不做微信小程序（需企业主体、备案、HTTPS 域名）
- ❌ 不做公网访问、不做端口映射（家里 Wi-Fi 够用；出门再看走 M6.5 Tailscale）
- ❌ 不改桌面端 HTML/CSS/JS，不改 `/api` 出参与路由
- ❌ 不做自动下单、抢购、内存读取（原项目红线不变）

## 1. 背景与现状

### 1.1 现状盘点（决定方案的关键事实）

| 项 | 现状 | 位置 | 对手机端的影响 |
| --- | --- | --- | --- |
| 服务绑定 | `127.0.0.1:8787` | [config.py:44](../backend/config.py) | 手机**连不上**，这是第一道坎 |
| 启动器 | `uvicorn --host 127.0.0.1` 写死 | [start.ps1:106](../start.ps1) | 需要新增 `-Lan` 开关，不能靠改 `.env` 绕过 |
| 前端托管 | `StaticFiles` 挂在 `/`，`html=True` | [app.py:121](../backend/app.py) | **新增 `frontend/m/index.html` 即自动可访问 `/m/`**，后端几乎不用改 |
| 页面布局 | 单断点 `@media (max-width: 860px)`，11 列表格 + 双栏 + 右侧抽屉 | [style.css:243](../frontend/assets/style.css) | 手机上不可用：横向滚动、触控目标过小 |
| 鉴权 | 无（`app.py` 注释明确"不做鉴权"） | [app.py:11-14](../backend/app.py) | 暴露到局域网前必须补 |
| PWA | 无 manifest、无 Service Worker | `frontend/` | 现在只能当普通网页 |
| 通知 | 页面内 `new Notification(...)`，靠前端轮询 | [app.js:661](../frontend/assets/app.js) | 页面一关/锁屏就失效 |
| 测试 | 124 个离线测试，含 CSS 级联回归 | `tests/` | 改动可回归，风险可控 |
| 图标 | 已有 `app-icon.png` / `app.ico` | `frontend/assets/` | 可复用生成 192/512 图标 |

### 1.2 为什么不能直接把桌面页面塞进手机

1. **11 列表格**：名称 + 口径 + 品质 + 当前价 + 今日 + 7 日 + 7 日区间 + 分位 + 机会分 + 操作，375px 宽下要么横向滚动，要么挤成 8px 字。
2. **双栏布局**：行情页"表格 + 排行榜"并排，手机上必须改成上下流式。
3. **右侧抽屉**：桌面从右侧滑出，手机应从底部全屏弹出，否则可视区只剩 60%。
4. **交互方式不同**：桌面靠 hover、右键、宽点击区；手机靠点击、滑动、返回手势。
5. **`app.js` 是单文件渲染**（表格行 DOM + 图表 SVG），移动端需要卡片 DOM 与触摸图表，逻辑分叉会让桌面端回归成本变高。

结论：**同一页面用 CSS 硬适配不划算**，独立移动页更干净（见 §4）。

### 1.3 已确认的产品决策（用户 2026-10-19 确认）

| 问题 | 答复 | 推导 |
| --- | --- | --- |
| 手机平台 | **Android 为主** | 推送走 ntfy/Bark；图标用 maskable PNG；测试用 Chrome |
| 使用范围 | **只在家同一 Wi-Fi** | 不需要公网、域名、证书；安全靠 token + 防火墙 |
| 核心诉求 | **随时看行情和价格曲线** | v1 只读优先：行情/详情/自选/健康；告警规则编辑降级 P2 |
| 后端运行 | **家里电脑 24 小时开着** | 不买云主机；重点是关睡眠、固定 IP、开机自启 |

## 2. 目标与非目标

### 2.1 目标（可度量）

| 编号 | 目标 | 验收指标 |
| --- | --- | --- |
| G1 | 手机能打开 | 手机 Chrome 访问 `http://<PC-IP>:8787/m/`，首屏 ≤ 2s（局域网） |
| G2 | 布局不崩 | 360 / 375 / 412 / 430px 四种宽度**无整页横向滚动**；竖屏为主，横屏不崩即可 |
| G3 | 行情可用 | 搜索、品质筛选、口径筛选、排序、只看可交易，全部可用；列表 111 条滚动流畅（≥ 50fps 观感） |
| G4 | 曲线可用 | 详情抽屉内 1h/6h/24h/7d/30d 切换，手指拖动有数值提示，图表不糊 |
| G5 | 自选可用 | 卡片上加/取消自选，自选页实时反映 |
| G6 | 不破坏桌面 | 桌面 4 视图 + 抽屉行为与改前一致；124 个测试全绿（新增测试另计） |
| G7 | 安全可控 | 开启 token 后，非本机访问 `/api/*`、`/docs` 必须带 token；关闭 token 时行为与现在完全一致 |
| G8 | 可安装到桌面 | 手机浏览器"添加到主屏幕"，图标/名称正确；能否无地址栏全屏取决于浏览器是否按 PWA 安装（HTTP 下不保证，见 §8.7） |

### 2.2 非目标（明确不做，避免扯皮）

- 不做原生 App（Kotlin/Flutter/RN）、不做应用商店上架、不做 APK 分发。
- 不做微信小程序（无企业主体，且会引入域名备案与 HTTPS 强制要求）。
- 不做公网暴露、不做端口转发、不做多用户/账号体系。
- 不做手机端告警规则"新建/编辑/删除"（P2，见 §5.6）；v1 只读展示规则与触发历史。
- 不做离线优先（无 Service Worker，见 §8.7 原因）；断网时显示错误态即可。
- 不做推送（M6.5 可选）。
- 不改数据采集、指标算法、告警判定、数据库结构。

### 2.3 约束

1. **零构建、零 CDN**：沿用现有约束（手写 SVG 图表、无 npm、无外链字体）。手机端也不引入框架与 CDN。
2. **中文注释**：与现有代码风格一致，注释说明"为什么"而不是"做什么"。
3. **安全默认值**：`auth_token` 默认为空 = 不启用鉴权，保证 `git clone` 后行为不变；启用后**默认只信本机**。
4. **不引入新依赖**：后端不新增 pip 包；图标生成可用现有 Pillow（tools/ 已有先例）。

## 3. 总体架构

### 3.1 部署拓扑（v1 局域网）

```
        ┌──────────────────────────┐
        │  Android 手机             │
        │  Chrome 打开 /m/         │
        │  （可"添加到主屏幕"）      │
        └────────────┬─────────────┘
                     │  http://192.168.x.x:8787
                     │  同一家庭 Wi-Fi，无公网
        ┌────────────▼─────────────────────────────────────┐
        │  家用电脑（24h 开机，仅专用网络配置文件）           │
        │  ┌────────────────────────────────────────────┐  │
        │  │ uvicorn  0.0.0.0:8787                       │  │
        │  │   ├─ /api/*    FastAPI 路由（不变）          │  │
        │  │   ├─ /         桌面看板（不变）               │  │
        │  │   └─ /m/       移动看板（新增）               │  │
        │  │   + 可选 TokenMiddleware（默认不启用）        │  │
        │  └────────────────────────────────────────────┘  │
        │  data/ammo.sqlite3（SQLite WAL，不变）            │
        └──────────────────────▲───────────────────────────┘
                               │ 每 10 分钟一次（出站）
                    ┌──────────┴──────────┐
                    │ derGame 公开只读接口 │
                    └─────────────────────┘
```

要点：

- **同源**：`/m/` 与 `/api/*` 同一个端口，**不需要 CORS**（沿用现有优势）。
- **零新增服务**：不新增端口、不新增进程、不新增数据库。
- **出站不变**：采集链路完全不动。

### 3.2 移动端内部结构（页面与路由）

```
/m/  (frontend/m/index.html)
│
├─ #/market   行情总览（默认）
│    ├─ 搜索 + 筛选面板（品质/口径/排序/只看可交易）
│    ├─ KPI 2×2
│    ├─ 弹药卡片列表 → 点卡片
│    └─ 排行榜（横向切榜单）
│
├─ #/a/{ammo_id}   详情（全屏覆盖层，带 hash，可返回/刷新）
│
├─ #/watch    自选
├─ #/alerts   告警（只读：规则 + 触发历史）
└─ #/health   数据健康
```

采用 **hash 路由**的原因：安卓返回键/返回手势天然可用、刷新不丢页面、详情可直达。不需要 History API 与后端 fallback 配合（避免刷新 404）。

### 3.3 数据流（与桌面完全一致）

```
页面加载 → GET /api/ammo?only_tradeable=1&sort=opportunity&order=desc&limit=200
            └→ 前端本地筛选/渲染（服务端已支持 q/tier/caliber/sort）
点卡片   → GET /api/ammo/{id}（权威详情）+ GET /api/price/{id}?range=24h
自选     → GET /api/watchlist → POST/DELETE /api/watchlist/{id}
选中区间 → GET /api/price/{id}?range=…（1h/6h/24h/7d/30d）
排行榜   → GET /api/rank?type=up|down|volatility|opportunity|cheap&limit=15
健康页   → GET /api/health（+ 可选 /api/health/pack-check）
```

## 4. 技术选型

### 4.1 候选方案对比

| 方案 | 做法 | 改动面 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A1 同页响应式** | 只改 `index.html` + `style.css`，表格在窄屏变卡片 | 桌面 DOM/JS 都要分叉 | 高：`.table-wrap`、抽屉、`renderTable` 全部要改；124 测试中的 CSS 回归测试容易被打破 | ❌ |
| **A2 独立移动页（选用）** | 新增 `frontend/m/`，复用 `/api` | 桌面零改动；移动端独立演进 | 低：出问题只影响 `/m/` | ✅ |
| **A3 原生/跨端** | Flutter / React Native / uni-app | 全量重写 | 高：2~4 周，图表/抽屉/4 视图二次开发 | ❌ |
| **A4 小程序** | 微信小程序 | 全量重写 + 备案 | 极高：企业主体、HTTPS 域名、审核 | ❌ |
| **A5 套壳 APK** | Capacitor 包 A2 | 半天增量 | 中：需 JDK/Android SDK、签名、更新要重装 | ⏸ 二期可选（M6.5） |

### 4.2 为什么 A2 可行（关键依据）

现有后端 `app.py:120-121` 已把 `frontend/` 整体挂载为静态目录且 `html=True`，因此：

- `frontend/m/index.html` → 自动可访问 `http://host:8787/m/`；
- 静态资源放 `frontend/assets/m/`（或复用 `frontend/assets/`）；
- **不改后端任何路由**，只新增可选中间件。

### 4.3 技术栈（刻意"倒退"的选择）

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 框架 | 无（原生 JS） | 项目既有约束是零构建、零 CDN；单页 4 视图不值得上框架 |
| 图表 | 手写 SVG（复用桌面 `drawChart` 思路） | 桌面已验证；触摸只需加 pointer 事件 |
| 样式 | 原生 CSS + CSS 变量 | 复用 `:root` 的配色 token（红涨绿跌） |
| 图标 | 内联 SVG（底部 tab） | 零请求、可随文字变色 |
| 路由 | hash 路由（~30 行） | 返回键可用，无需后端 fallback |
| PWA | manifest + 图标（无 SW） | HTTP 局域网下 SW 无法注册（见 §8.7） |

## 5. 信息架构与页面设计

### 5.1 全局框架

```
┌─────────────────────────────────────┐
│ ● 数据 12s 前更新          ↻ 刷新   │  顶栏（sticky，48px）
├─────────────────────────────────────┤
│  [搜索名称或口径…]                  │  搜索（仅行情页）
├─────────────────────────────────────┤
│                                     │
│           页面内容区                 │  main（可滚动）
│        padding-bottom: 64px          │
│                                     │
├─────────────────────────────────────┤
│  行情   自选   告警   健康           │  底部 tab（固定，4 项）
└─────────────────────────────────────┘
```

规范：

- 底部 tab 高度 56px + `env(safe-area-inset-bottom)`；
- 顶栏高度 48px，滚动时保持可见；
- 所有可点元素 ≥ 44×44px，间距 ≥ 8px；
- 页面最大宽 560px，桌面浏览器打开时居中（不至于拉成一条）；
- 深色主题沿用 `--bg: #0f1621`，`<meta name="theme-color">` 同色（状态栏融合）。

### 5.2 行情页 `#/market`

**信息优先级**：当前价 > 今日/7 日涨跌 > 分位（贵/便宜）> 机会分 > 口径/品质。

卡片线框：

```
┌─────────────────────────────────────┐
│ ★  .300BLK          金 · 7.62x35mm  │  ← 名称（长名省略号）、品质徽标、口径
│                     4,871 / 发      │  ← 当前价（右对齐，大字）
│ ▓▓▓▓▓▓░░░░░  63%   今日 +2.1%       │  ← 分位条 + 标签、今日涨跌（红涨绿跌）
│ 7 日 -4.8%   机会 72   12s 前        │  ← 7 日、机会分、新鲜度
└─────────────────────────────────────┘
```

交互：

| 操作 | 行为 |
| --- | --- |
| 点卡片任意处 | 打开详情 `#/a/{ammo_id}` |
| 点星标 | 切换自选（`POST/DELETE /api/watchlist/{id}`），不跳转 |
| 下拉 | 不实现下拉刷新（浏览器自带）；用顶栏"刷新"触发 `POST /api/ingest/trigger` |
| 搜索输入 | 250ms 防抖，`AbortController` 取消旧请求 |
| 筛选 | 搜索框下方折叠面板（品质 chips / 口径 select / 排序 select / 只看可交易 switch），展开高度 ≤ 40% 屏 |
| 排行榜 | 卡片列表下方"榜单"区块：5 个横向 chips 切换榜单，列表 15 条，点击进详情 |

KPI 区（2×2）：数据新鲜度（秒/分）、可交易物品数、今日上涨家数、今日下跌家数。口径与桌面一致，数字来自 `/api/ammo` 与 `/api/health`。

空态/异常态：

- 搜索无结果 → "没有匹配的弹药"+ 清空筛选按钮；
- API 失败 → 顶部黄条"数据请求失败，正在重试" + 自动重试 1 次（3s）；
- token 失效 → 弹出登录层（§7.3）。

### 5.3 详情页 `#/a/{ammo_id}`

全屏覆盖层（`position: fixed; inset: 0`），从底部滑入 220ms，`Esc`/返回键关闭。

```
┌─────────────────────────────────────┐
│ ×   .300BLK 金 · 7.62x35mm          │
│                                     │
│ [1h] [6h] [24h] [7d] [30d]          │
│ ┌─────────────────────────────────┐ │
│ │      折线 + 区域渐变             │ │
│ │   拖动：10:00  4,871            │ │
│ └─────────────────────────────────┘ │
│ 7 日区间 444 ~ 4,871   分位 63%     │
│ ┌────────────┬────────────┐         │
│ │ 今日 +2.1% │ 7 日 -4.8% │         │
│ │ 24h 均线   │ 波动率     │         │
│ │ ...14 项指标 2 列 ...   │         │
│ └────────────┴────────────┘         │
│        [ ★ 加入自选 ]               │  底部固定按钮
└─────────────────────────────────────┘
```

图表要求：

- 复用桌面指标口径：`price` / `unit_price` 同时展示，注明单位（`unit_price_label`）；
- 触摸：`pointerdown/move/up` → 最近点高亮 + 数值气泡，松手 1.5s 后消失；
- 数据点上限：30d 约 720 点，绘制前按像素宽度采样到 ≤ 300 点（沿用桌面采样逻辑）；
- 空序列：显示"暂无足够数据"而不是空白坐标；
- 详情抽屉的 14 项指标中，`source_index_7zf` 必须标注"数据源自报，定义未知"，**不参与任何计算**（沿用 README 的教训）。

### 6.1 接入步骤（一次性配置，约 30 分钟）

## 7. 安全设计

### 7.1 威胁模型（自用场景）

| 威胁 | 可能性 | 影响 | 对策 |
| --- | --- | --- | --- |
| 同 Wi-Fi 的家人/访客设备误开 8787 | 中 | 看到行情数据（低敏感） | 可选 token；路由器访客网络隔离 |
| 邻居蹭网后扫描内网 | 低 | 同上 | Wi-Fi 强密码 + WPA3；token |
| 路由器被误做端口转发 → 公网暴露 | 低 | 数据公开、被扫 `/docs` | 不做端口映射；`-Lan` 启动时打印提醒 |
| `/docs` 暴露接口结构 | 中 | 增加被探测面 | token 开启时保护 `/docs` 与 `/openapi.json` |
| token 泄露（手机丢失） | 低 | 可读数据 | 改 `.env` 换 token 重启即可 |

数据本身是公开行情聚合，**没有账号、没有支付、没有个人隐私**，所以安全目标是"不被陌生人随便看"，而不是"防拖库"。

### 7.2 鉴权机制（可选、默认关闭）

配置：

```dotenv
# .env，留空 = 不启用（保持现状）
AUTH_TOKEN=
```

规则：

1. `AUTH_TOKEN` 为空 → 中间件直接放行，行为与现在**完全一致**；
2. 非空 → 以下请求需要 token：
   - `/api/*` 全部；
   - `/docs`、`/openapi.json`、`/redoc`；
3. **本机回环地址免 token**（`request.client.host in {"127.0.0.1", "::1"}`）——
   桌面端零改动，本机体验不变；
4. 静态资源（`/m/`、`/assets/`、favicon、manifest）**不拦**——它们不含数据，拦了会导致登录页都加载不出来；
5. token 传递方式：请求头 `X-Auth-Token: <token>`（前端 `localStorage` 保存）；
6. 比较用 `hmac.compare_digest`（常量时间，防时序侧信道）；
7. 失败返回 401 + `{"detail": "需要访问令牌"}`，不加 `WWW-Authenticate` 挑战（避免浏览器弹原生对话框）。

生成 token：

```powershell
& $py -c "import secrets; print(secrets.token_urlsafe(24))"
```

中间件骨架（放在 `backend/app.py`，挂载前注册）：

```python
PUBLIC_PREFIXES = ("/m", "/assets", "/favicon", "/manifest.webmanifest")
PROTECTED_PREFIXES = ("/api", "/docs", "/redoc", "/openapi.json")

class TokenMiddleware(BaseHTTPMiddleware):
    async def dispatch(self, request, call_next):
        token = get_settings().auth_token
        if not token:
            return await call_next(request)
        path = request.url.path
        if not path.startswith(PROTECTED_PREFIXES):
            return await call_next(request)
        client = request.client.host if request.client else ""
        if client in ("127.0.0.1", "::1", "localhost"):
            return await call_next(request)
        got = request.headers.get("X-Auth-Token", "")
        if hmac.compare_digest(got, token):
            return await call_next(request)
        return JSONResponse({"detail": "需要访问令牌"}, status_code=401)
```

> 注意：`-Dev` 分离模式由 `scripts/serve_frontend.py` 反代 `/api` 到 `127.0.0.1`，
> 会让所有请求看起来都来自本机、从而绕过 token。**`-Dev` 仅限本机开发**；
> 手机访问必须用一体模式（`-Lan` 强制一体模式，见 §8.1）。

### 7.3 前端登录层

- 任何 API 返回 401 → 显示全屏登录层（输入 token + "记住"）；
- 成功后 `localStorage.setItem("bullet_token", token)`，所有 fetch 自动加头；
- 顶部"设置"入口可清除 token（换 token 时用）；
- 登录层不依赖网络（纯本地渲染），且不拦截静态资源；
- **桌面端不提供登录层**：开启 token 后，桌面看板仍可本机正常使用（回环免 token），
  但从局域网打开桌面看板会看到"数据请求失败"。这是刻意取舍——桌面端定位就是本机；
  手机请用 `/m/`。

### 7.4 其他加固

| 项 | 做法 |
| --- | --- |
| 日志 | 不打印 token；`uvicorn` access log 只记路径 |
| `/api` 根 | 保留，但不在其中暴露额外信息（现状已如此） |
| 限流 | v1 不做（局域网自用）；M6.5 若公网再加 |
| 缓存 | `index.html` 不缓存（`Cache-Control: no-cache`），静态资源可 ETag |
| 错误页 | 不返回堆栈（FastAPI 默认行为，保持） |

### 8.7 PWA 规格（"快捷方式级"，不是完整 PWA）

`manifest.webmanifest`：

```json

  "short_name": "子弹监控",
  "start_url": "/m/",
  "scope": "/m/",

  "background_color": "#0f1621",
  "theme_color": "#0f1621",
  "icons": [
    { "src": "/assets/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/assets/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any maskable" }
  ]
}
```

**为什么 v1 不注册 Service Worker**：

- SW 只在**安全上下文**（HTTPS 或 localhost）可用；局域网 `http://192.168.x.x:8787` 不满足，注册会失败；
- 强行注册只会在控制台报错，形成"看起来做了 PWA 其实没做"的假象；
- 因此 v1 只做"添加到主屏幕"快捷方式（Chrome 会用 favicon/title 作为图标名，`display: standalone` **不保证**生效）。

**解锁完整 PWA 的条件**（M6.5）：有 HTTPS 入口（Tailscale 证书 / Cloudflare Tunnel）后，再加 SW：

- 缓存 `/m/`、`/assets/*`（app shell）；
- `/api/*` 走"网络优先，失败回缓存"，缓存 24h 内数据；
- 此时才能做 Web Push（§12 推送路线）。

### 8.9 推送（M6.5 可选，仅设计不实现）

若后续要做"价格到位手机响"，**不要因此去做原生 App**：

| 方案 | 依赖 | 实现 | 说明 |
| --- | --- | --- | --- |
| ntfy | 公网 ntfy.sh 或自建 | `notify.py` 增加 `send_ntfy()`：POST 到 `https://ntfy.sh/<topic>` | Android 最省事；topic 当密钥，别用可猜名字 |
| Bark | Bark App | POST `https://api.day.app/<key>/<title>/<body>` | iOS/Android 都有客户端 |
| Web Push | HTTPS + SW + VAPID | 服务端保存 subscription，触发时推送 | 体验最好，但依赖 M6.5 的 HTTPS |

优先 ntfy：不依赖本机能被外网访问，也不需要 HTTPS 入口，`notify.py` 的通道契约（`send(payload)`）已预留。

### 附：本方案的三个关键判断（写给未来回看的自己）

1. **不重写**：这个项目的资产是后端数据链路与已验证的指标口径，前端只是展示层。手机端复用 API，风险最小、收益最快。
2. **先连通再美化**：M6.0 用现有页面在真机上打开，能提前暴露 80% 的环境问题（防火墙、网段、IP），比写完 UI 再调试便宜得多。
3. **诚实对待 HTTP**：局域网 HTTP 下没有安全上下文，就没有完整 PWA、没有推送。文档里写清楚边界，比假装"手机 App 已完成"更有价值；真要那两样，M6.5 用 Tailscale 的 HTTPS 一次性解决。
